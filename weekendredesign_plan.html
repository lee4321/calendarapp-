Plan: configurable weekend days (ISO 8601)

Context

The CalendarApp already has a weekend_days field on CalendarConfig, a --weekend-days CLI flag on several subparsers, and a get_weekend_days() resolver. But the field's documented convention ("ISO weekday") is wrong — internally it stores Python date.weekday() values (0=Mon..6=Sun), while the user-facing spec calls for true ISO 8601 (1=Mon..7=Sun, Sat/Sun = 6, 7). This mismatch is currently latent because nothing exercises the boundary, but it will silently corrupt configs as soon as users start writing [6, 7] expecting Sat/Sun.

The design doc at weekendredesign.md proposes standardizing on ISO 8601 (1–7) at every external surface (CLI, YAML, docs, error messages) and keeping Python weekday() (0–6) as an internal-only form converted at one chokepoint. This plan implements that design, with corrections from a verification pass against the actual codebase (line numbers, parser inventory, theme count).

Approach

One conversion site. The only place that bridges ISO 1–7 → Python 0–6 is CalendarConfig.get_weekend_weekday_set(). Everything outside config — CLI, YAML, validation errors, docs — speaks ISO 1–7. Every comparison site speaks Python 0–6 via d.weekday() in <set>.

Weekly visualizer respects weekend_days for classification, but grid geometry stays driven by weekend_style (per design doc §7). weekend_days controls day classification across every visualizer — weekly shading/hash patterns/holiday styling, blockplan/compactplan/excelheader visible-day filtering, mini/text-mini workweek filtering. A Fri/Sat config with weekend_style=2 will still put Sat/Sun in the half-columns geometrically, but Friday will be shaded as a weekend (and Sunday will not). This is a valid combination; emit no warning.

Weekly classification already flows through shared/day_classifier.classify_day() (called at visualizers/weekly/renderer.py:199), which reads config.get_weekend_days(). Once that resolver is updated, weekly weekend shading automatically respects weekend_days with no further weekly-renderer changes. The remaining isoweekday() checks in weekly (lines 721, 723, 806) are week-start detection for fiscal labels and grid boundaries — those stay driven by weekend_style and are not touched.

Date-range snapping in shared/date_utils.py stays as-is (per design doc §8). It already uses isoweekday() (1–7), so it's incidentally already ISO-correct; we just don't entangle it with weekend_days.

Changes

1. config/config.py

  • Field docstring at line 118–123: replace "ISO weekday: 0=Mon..6=Sun" with "ISO 8601 weekday: 1=Mon..7=Sun". Default None → derive from weekend_style. Example default [6, 7].
  • __post_init__ validation at ~line 1091–1102: change range check from 0 <= d <= 6 to 1 <= d <= 7. Keep duplicate check. Update error message to reference 1–7.
  • Rename get_weekend_days() → get_weekend_weekday_set() at line 1144. Body becomes: 
    def get_weekend_weekday_set(self) -> frozenset[int]:
    """Resolve weekend days as Python weekday() values (0=Mon..6=Sun).
    Converts internally from ISO 8601 storage (1..7)."""
    if self.weekend_days is not None:
        return frozenset((iso - 1) % 7 for iso in self.weekend_days)
    if self.weekend_style == 0:
        return frozenset()
    return frozenset({5, 6})  # Sat, Sun
  • Add is_weekend(d: date) -> bool helper next to it: return d.weekday() in self.get_weekend_weekday_set().

5. Theme YAMLs (optional / documentation only)

Adding base.weekend_days to YAMLs is optional — omitting it preserves current behavior. We will not touch the 19 existing theme files in this change. Document the new key in USER_GUIDE.md (or wherever theme keys are documented) and let users add it when needed. Explicit empty list [] disables weekends in a theme.

  • Weekly-specific test: with weekend_days=[5] (Fri only) and weekend_style=1 (7-col grid), render a week containing a Friday and assert (a) Friday has the weekend shade applied in the rendered SVG and (b) Saturday/Sunday do not — confirming classification respects weekend_days while geometry stays driven by weekend_style.
  • Theme-engine round-trip: load a minimal theme dict {"base": {"weekend_days": [5, 6]}} and assert config.weekend_days == [5, 6].

7. Migration note

This is a breaking change to the --weekend-days flag (was 0–6, now 1–7) and to the weekend_days config field's accepted range. The flag is recent. The validation error message will explicitly say "ISO 8601 (1=Mon..7=Sun)" so users hitting the boundary get an actionable message. No silent reinterpretation, no compat shim.

Mention this in changelog.md and update the field docstring + any user-facing docs that quote 0–6.
