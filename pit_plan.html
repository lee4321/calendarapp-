1. Goal & Scope

Build a new visualizer named PIT (Points in Time) that produces SVG output stylistically aligned with the labella.py example gallery — a clean axis line, a marker per event, and a curved leader joining each marker to a non-overlapping label box.

PIT is intentionally narrower than the existing timeline visualizer:

DimensionExisting timelineNew pit
Single-day eventsYes (callouts)Yes — primary citizen
MilestonesYes (diamond marker)Yes — diamond or DB icon
Multi-day durationsYes (duration bars)No — out of scope
Rollups / WBS / icon bandYesNo — deferred
Fiscal period / quarter bandsYesNo — deferred
Axis directionshorizontal + verticalhorizontal + vertical
Label sidesprimary / secondary / bothprimary / secondary / both
Date scaleLinear over project rangeLinear over project range
Custom marker icons NEWNoYes — per-event, per-rule, or per-side
Reuse, don't rebuild. The recent timeline refactor already vendors labella (vendor/labella/) and provides reusable axis-direction primitives (visualizers/timeline/orientation.py) and a labella adapter pattern. PIT lifts those primitives, not duplicates them.

2. Visual Design

Vertical, Side.BOTH — date opposite the label

│ │ . ┌────────────────┐ Apr 1 ( )──────▶│ Milestone 1 │ ' └────────────────┘ │ ┌────────────────┐ . │ Milestone 2 │◀──────( ) Apr 27 └────────────────┘ ' │ . ┌────────────────┐ May 15 ( )──────▶│ Release │ ' └────────────────┘ │ ▼

Reference: text_timeline.txt. Each date sits at the marker's Y, on the opposite side of the axis from its label. Note the marker-end arrowheads: ▶ on each leader's label end and ▼ at the axis tip.

Vertical, Side.PRIMARY — date still opposite

│ . ┌──────────────┐ Jan 12 ( )──────▶│ Q1 Kickoff │ ' └──────────────┘ │ . ┌──────────────┐ Mar 04 ( )──────▶│ Design freeze│ ' └──────────────┘ │ . ┌──────────────┐ Apr 18 ( )──────▶│ Beta Cut ◆ │ ' └──────────────┘ │ ▼

When all labels are on one side, all dates sit on the opposite side, each at the Y of its leader's intersection with the axis.

Horizontal, Side.BOTH — dates opposite

[Q1 Kickoff] [Beta Cut] \ \ \ \ ──●────●─────●────◆───★───●──▶ Jan12 Apr 1 May 4 Jul 9 / / / / [Audit] [Launch ★]

Horizontal axis: dates are placed on the opposite side of the axis from each event's label, at the X of the dot. The axis ends in a marker-end arrowhead.

Today line (themeable + offsettable)

│ . ┄┄┄┄┄┄┄┄┄┄┄┄ "today" ← label is themeable │ ← stroke: red, dashed (theme-set) │ ▼ Config: pit_today_date overrides "now" (lets you render a future-state deck)

All stroke attributes (color, width, dasharray, opacity, linecap) plus label text and label position are theme-driven. pit_today_date overrides the natural "now" so presentations can be prepared with a forward-looking "today".

Visual primitives

  • Axis line UPDATED — single thin stroke spanning the project date range, with ticks at the chosen timeband granularity (see §4). Accepts independent SVG marker-start and marker-end references, each with its own size. Useful patterns: a small dot or tick on marker-start (the "origin" tip) plus an arrow-head on marker-end (the "future" tip), with separate sizes. For v1 a built-in arrow-head marker is auto-injected into <defs> per (kind, color, size) tuple; theme fields accept "arrow-head", "none", or any user-defined marker id.
  • Event marker UPDATED — by default a filled circle at the date's axis position. May be replaced by an SVG icon from calendar.db's icons table. Resolution order:
    1. Per-event event.icon (DB column) if set.
    2. Style-rule marker_icon: "name" (matches today's pattern: rule mechanism).
    3. Config pit_default_event_icon (theme-overridable).
    4. Fallback: filled circle of radius pit_dot_radius.
  • Milestone marker UPDATED — by default a filled diamond. Replaceable by a DB icon via the same precedence chain rooted at pit_default_milestone_icon (and per-rule milestone_icon: "name"). Icon glyphs are colored using the same color resolution path as the diamond fill, so themes and rules continue to drive color even when the shape comes from a glyph.
  • Leader UPDATED — labella's bezier path from marker to label box. Now exposes a full SVG stroke attribute set:
    • stroke (color) — accepts palette:NAME:INDEX, CSS name, or hex.
    • stroke-width
    • stroke-dasharray (e.g. "4,2" for dashed leaders)
    • stroke-opacity
    • stroke-linecap (butt / round / square)
    • stroke-linejoin (miter / round / bevel)
    Applied from a single resolved LeaderStyle per placement, with precedence: per-rule leader: {...} → side default (theme_pit_leader_primary / _secondary) → global theme_pit_leader → module defaults.
    Leaders accept both marker_start and marker_end, independently sized UPDATED. marker_start sits at the axis end (next to the dot) — useful as a small filled circle to "cap" the leader on the axis. marker_end sits at the label end — matching the ▶ in the text_timeline.txt reference. SVG auto-rotates each marker so an arrow-head points toward its respective endpoint, in both horizontal and vertical layouts and on both sides. Per-side and per-rule overrides may set either or both.
  • Date label NEW — short date string (format from theme pit.date_format, default "MMM D") drawn on the opposite side of the axis from each event's label. Placement rules:
    • Same Y (vertical axis) / same X (horizontal axis) as the marker — i.e. the intersection of the leader with the axis, not the (force-displaced) Y/X of the label box.
    • Side.BOTH: a label on the primary side gets its date on the secondary side, and vice-versa (see top-left ASCII diagram, matching text_timeline.txt).
    • Side.PRIMARY only: all dates appear on the secondary side. Side.SECONDARY only: all dates appear on the primary side.
    • Text-anchoring is automatic: horizontal layout uses text-anchor="middle"; vertical layout uses text-anchor="end" on the left and "start" on the right.
    • Theme: pit.date_text exposes color, font_name, font_size, and offset (distance from axis to the date text baseline). All accept palette:NAME:INDEX references for color.
  • Label box UPDATED — task name (bold), optional notes (light), and the formatted date. Supports the same stroke/fill/pattern/opacity vocabulary as weekly day-boxes — see §5.
  • Today line UPDATED — perpendicular line at the configured "today" date. Fully theme-driven:
    • Full stroke vocabulary: color, width, dasharray, opacity, linecap, linejoin — all accept palette references.
    • Label text: pit.today_line.label (default "today") — set to "" or null to suppress.
    • Label styling: label_color, label_font_name, label_font_size, label_position (start / middle / end along the line).
    • Marker-start & marker-end on the line are independently configurable UPDATED. Typical use: an arrow-head on marker-end pointing "into the future", and a small cap on marker-start at the axis. Each has its own size field.
    • Date override: pit_today_date (CLI: --today-date YYYY-MM-DD) replaces the natural now. Use case — preparing a presentation slated for a future board meeting with the "correct" today indicator.

SVG marker defs (marker-start + marker-end) UPDATED

For v1 a single built-in marker kind — arrow-head (an equilateral triangle, configurable size + fill color via theme) — is auto-injected into <defs> on first use. Inspired by the ▶ / ▼ arrowheads in text_timeline.txt. The injector deduplicates by id marker-{kind}-{color}-{size}, mirroring the existing pattern-def deduplication path (see MEMORY.md → "SVG Pattern Decoration"). Different sizes produce different <marker> entries, so the axis-end and leader-end arrows can render at distinct dimensions on the same SVG without clobbering each other.

Every stroked primitive exposes both a start and end slot, each independently sized:

Theme slotApplies toDefault
pit.axis.marker_start + marker_start_sizeAxis origin tip"none", size 4.0
pit.axis.marker_end + marker_end_sizeAxis terminal tip (▼ in the reference)"arrow-head", size 6.0
pit.leader.marker_start + marker_start_sizeThe axis end of every leader (next to the dot)"none", size 3.0
pit.leader.marker_end + marker_end_sizeThe label end of every leader (▶ in the reference)"arrow-head", size 5.0
pit.today_line.marker_start + marker_start_sizeThe axis-anchored end of the today line"none", size 4.0
pit.today_line.marker_end + marker_end_sizeThe free end of the today line"none", size 6.0

Per-side overrides (leader_primary.marker_{start,end}{,_size} / leader_secondary.*) and per-rule overrides (leader: { marker_start: "...", marker_end_size: 8 }) follow the same precedence chain as the rest of LeaderStyle. Setting any slot to "none" emits no SVG attribute for that end. Sizes are SVG user units; the marker's markerWidth / markerHeight are set to the size value and refX/refY are chosen so the marker tip lands exactly on the line endpoint.

4. CLI Surface UPDATED

New subcommand pit. Reuses the shared visualizer argument groups already wired in ecalendar.py rather than re-declaring duplicates. The shared groups are added by the per-view loop around ecalendar.py:367 (for view_parser in (weekly, mini, ..., timeline, blockplan, compactplan, ...)) — PIT joins that loop.

Deliberately not re-introduced as PIT-specific flags:
  • --milestones, --rollups, --WBS, --includenotes, --ignorecomplete, --noevents, --empty — these are the canonical content-filter flags already used by timeline/blockplan/compactplan; PIT honors them via the same shared block.
  • --nodurations — meaningless for PIT (durations are never drawn). Filtering happens unconditionally in the renderer's event filter step.
  • --show-notes / --no-notes — superseded by the existing --includenotes flag.
  • --date-format (as a CLI flag) — covered by the theme's pit.date_format; not promoted to CLI for v1.

5. Config & Theme Integration UPDATED

5.1 Palette & pattern access

Every PIT color slot accepts the project's existing reference syntax. Resolved at render time through ecalendar._resolve_palette_overrides() against db_access.get_all_palettes():

  • Hex / CSS name — e.g. "#2d5fae", "steelblue"
  • Single palette index — "palette:Set1:3" (named palette in the palettes DB table)
  • Bulk palette list — top-level event_palette, milestone_palette, label_palette entries that hand out colors round-robin to events (mirrors the existing month_palette / fiscal_palette / group_palette mechanism)

SVG patterns from the patterns DB table are usable as label-box fills via the same _ensure_svg_pattern_def code path already used by the weekly day-box hash decoration (see MEMORY.md → "SVG Pattern Decoration"). Pattern names referenced by PIT include all 35 patterns shipped in calendar.db.

6. Labella Integration Notes

  1. Build Node(idealPos, width, data=event) for each event.
    • Horizontal: idealPos = pixel offset from axis start; width = measured text width + padding.
    • Vertical: idealPos = pixel offset down the axis; width = line-height extent.
  2. Run Force(nodes, options={"lineSpacing": ..., "minPos": 0, "maxPos": axis_length}).compute().
  3. Build leader paths via Renderer(direction=labella_direction(direction, side), nodeHeight=..., ...).layout(nodes) then .generatePath(nodes) — emit the bezier d in axis-local coords.
  4. Pair each placement with the absolute axis_origin and wrap leader paths in <g transform="translate(ox,oy)"> at render time. Identical to the proven timeline approach.
  5. Side.BOTH handling: partition events with chronological alternation (mirror _partition_for_both() in visualizers/timeline/labella_adapter.py) and run labella twice — once per side — with opposing directions.
  6. Per-marker stroke styling is applied after labella returns geometry — labella sees only positions and widths.

10. Decisions RESOLVED

The v2 open questions have been resolved. The decisions below are now part of the spec.

#QuestionDecision
1 How to handle multi-day events? Drop entirely. The renderer's event-filter step removes any event with start != end before the labella pass. A summary line is emitted on stderr — "PIT: skipped N multi-day events (use the timeline visualizer for durations)" — so the omission is never silent. Documented as a hard limitation in USER_GUIDE.md.
2 Density limit when labella struggles to converge. Hard cap at 80 events per side. The adapter counts events after the side-partition step. If either side exceeds 80, the renderer:
  • logs a WARNING via the project's standard logger,
  • writes the same warning into the SVG <desc> metadata block (so the SVG itself records that it was over-budget),
  • still proceeds with the layout (labella's own bail-out remains the final safety net).
Constant: PIT_MAX_EVENTS_PER_SIDE = 80 in pit/labella_adapter.py so it is testable and tunable.
3 Icon sizing for non-square DB glyphs. Scale to fit the longest side, then center on the marker point. Implementation in pit/markers.py::draw_marker():
  1. Parse glyph viewBox; compute scale = pit_marker_size / max(viewBox.w, viewBox.h).
  2. Translate so glyph's viewBox center coincides with the marker (x_dot, y_dot).
  3. Apply colorization via the existing fill="#000" → resolved color substitution.
Test test_pit_icon_sizing verifies a 16×8 glyph and an 8×16 glyph both render with their longest side at pit_marker_size and centered on the dot.
4 Label fill precedence when both an explicit color and a palette are set. Explicit per-rule > per-side > label_fill_color > label_palette (round-robin). Implemented in pit/renderer.py::_resolve_label_fill(). The palette is only consulted when every more-specific source returns None. Round-robin order is the chronological event order (stable, deterministic). Test test_pit_label_fill_precedence exercises all four levels with overlap.

12.2 Stable data-* attributes

Beyond classes, PIT emits a small set of stable data-* attributes on the callout group so external CSS can target individual events:

   data-event-id="42"
   data-event-date="2026-04-01"
   data-milestone="false"

   <path class="ec-callout-leader" .../>
   <rect class="ec-callout-box"   .../>

}

/* hide notes on tiny print runs */

  .ec-event-notes { display: none; }
}

/* swap axis color without re-rendering */
.ec-axis-line { stroke: navy; }

12.4 The inline-style footgun

CSS beats SVG presentation attributes in the cascade — but inline style="" beats CSS classes. The existing renderer protects against this by listing classes that always carry per-instance inline styles in _INLINE_STYLED_CLASSES (renderers/css_generator.py:21) — for those classes, CSS rule emission is suppressed entirely so external stylesheets can take effect.

For PIT, the following classes are added to _INLINE_STYLED_CLASSES because the renderer writes per-instance presentation attributes that must survive external CSS overrides:

  • ec-pit-event-marker — fill is set per-event by the rule engine / palette round-robin.
  • ec-milestone-marker — same.
  • ec-callout-leader — stroke is per-side / per-rule.
  • ec-callout-box — fill is per-event (palette round-robin) and pattern URLs are per-event.

For these classes, PIT uses css_class= to tag the element (so external CSS can still target it by selector) but writes the actual fill/stroke/etc. as SVG presentation attributes. End users supplying an external stylesheet must use !important to override per-instance styling on those four classes — documented in USER_GUIDE.md.

The "always-themeable" classes (no inline style, fully CSS-driven) are:

  • ec-axis-line, ec-axis-tick, ec-tick-label
  • ec-event-name, ec-event-notes, ec-event-date
  • ec-today-line, ec-today-label
  • ec-pit-marker-arrow-head
